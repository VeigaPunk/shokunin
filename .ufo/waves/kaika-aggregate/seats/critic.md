## Identity, snapshot, and selector hazards

1. **No implied 21-row verdict from discovery or a fleet exit code.** R9 `--all` discovers direct children of the script-derived `MAIN_ROOT`; in this worktree that root is the aggregator worktree, not necessarily `/home/vgpnk/Projects/shokunin`. The requested per-lane `--snapshot` runs avoid that ambiguity only if their input paths are the canonical physical lane roots. `--all --repos ''` is also a valid empty selection in `parseArgs`; the `--all` branch can then produce no lane rows and combine an empty result set to exit 0. A zero fleet exit without asserting a nonempty, exact expected lane set is not coverage.
2. **`--snapshot` has no own-git-root guard.** `ownGitRoot` is called only for default-discovered live runs (`:552-568`); `runSnapshot` does `git rev-parse` and `git archive` without proving the selected directory is that child's repository. Git can resolve through an ancestor. A bad path/selector can therefore measure a parent tree under a child label. Before claiming physical-lane coverage, prove each canonical path resolves to its own git top level and map one unique repo ID to one unique path.
3. **Only full commit IDs are safe selectors.** `runSnapshot` resolves the user-supplied selector, then archives that same string (`:594-607`). A mutable branch/tag can move between those operations, so the printed `full` revision could disagree with the archived tree. The three visible R12 audit commands used full SHA selectors; require that for all rows. Also avoid `--label`: it overrides the basename-derived identity (`:841`, `:593`), so labels must not substitute for path-to-repo identity.
4. **A new snapshot is not a frozen expected-verdict reproduction.** `corpus-gate.expected.json` has only the prior frozen entries; each of the three visible R12 audits reports `expect … ABSENT`. That is an honest fresh recomputation at the exact archive revision, not a drift check against an independent expected finding set. The gate's selftest does not freeze each new lane result.
5. **The old 6/7 evidence is historical, not a current 21-lane substitute.** W1 `aggregator-state.md:71-83,148-170` records the earlier 6/7 verdict practice and a separate 21-lane live-worktree sweep with three provisional trees. The six R9 lesson records name older commits: `kengaku f09ff1f`, `kotoba 63ceba7`, `kumitate e0e5de1`, `kake a209441` (and a separate earlier dirty revision), `kasegi b7180b0`, `kagi 4391b3b`. They cannot stand in for current exact-HEAD runs. They also show recurring pitfalls: Kasegi's missing source root left citations unresolvable; Kake/Kagi had dirty-worktree-only evidence; and literal `op://` findings were still rule-8 failures even when described as schematic. Preserve those as exact rule outcomes, not as semantic passes.

R9 `corpus-gate.mjs:62-124,177-184` implements only r2/r4/r7/r8-literal/r10/SHONEN form. It explicitly does not evaluate r1 (source quality), r3 (falsifiability), r5 (negative-claim sweep), r6 (quote location), r9 (append-only/history), verifier independence, or SHONEN truth.
