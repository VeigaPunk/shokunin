Design points behind the diff:

* **Dynamic universe, no fixed list.** Inclusion in `prompts-index.txt` and
  `state-counters.txt` is decided by the lane-id grammar alone, the same grammar the checker
  uses to admit a lane into `_lane_universe` (base `LANES` ∪ roster ids ∪ `.ufo/state/*.round`
  counters ∪ lanes named by a dispatch/complete line or a prompt file, A:42). A lane the driver
  mints mid-round is a snapshot row from its first dispatch, so the snapshot cannot go silent
  about a lane the gate itself adjudicates.
* **`wrap <lane> round=N complete`.** No code: the log rule already keeps every line whose
  leading timestamp parses, byte-for-byte, and `kept_log_lines()` rewrites nothing. Counters
  are launch/steer evidence only (`RE_DISPATCH`), so a wrap line never raises a counter --
  asserted by a fixture lane (`kiri`) that exists *only* as a wrap line at round 4.
* **Ordering.** `prompts-index.txt`, `state-counters.txt` and the pinned debt triples are in
  deterministic lexical order. Base-lane roster order is not part of the frozen schema: the
  checker compares baselines as a set (`_compare_baseline` → `_canon_debt` → row membership),
  and the checker's own `lane_sort` exists only for presentation.
* **Boundary kept from r13.** A prompt file whose lane token is outside the grammar (uppercase,
  punctuation) stays out of `prompts-index.txt`, exactly as before; the index claims parseable
  lane ids. No real prompt name is affected (all `.ufo/prompts/*-round-N.md` lanes parse).
* **`lane_round: null` accepted in the pinned triple.** The round-15 checker emits lane-less
  debt rows (`history_pin_*`: `lane="-"`, `lane_round=None`) and copies both fields verbatim
  into the compared triple, so the pinned unit must round-trip them. Without this, derived mode
  could not run at all against the r15 checker.

## 4. Findings on `.ufo/waves/round-15/closure-check.py` (reported, not edited -- outside this task's write scope)

**F1 (fixed in the generator).** `analyze`'s result dict sorts `unrowed` with the raw
`lane_round`, and the checker emits lane-less debt rows, so `canon_debt`'s integer-only rule
made derived mode impossible against the r15 checker:
`debt row has no integer lane_round: {'lane': '-', 'lane_round': None, 'class': 'history_pin'}`.
Fixed as described above; after the fix a derived run over a fixture mirror completes:
`exit=1 debt=[{lane:"-",lane_round:null,class:"history_pin"},{lane:"kagi",lane_round:1,class:"prompt_untracked"}]`.

**F2 (checker defect -- latent arm open, crash closed on head).** Naming it precisely, because
the first write-up of this section was too broad: sorting a list whose `lane_round` values are
*all* `None` never compares them (`(-1, None) == (-1, None)` short-circuits), so an unreadable
prompt name alone does not crash `analyze`. The `TypeError: '<' not supported between instances
of 'NoneType' and 'int'` needs a **mixed tie**: two `unrowed` rows with the same `lane_sort`
where one carries an integer `lane_round` -- e.g. an off-roster lane's `unrowed_terminated` row
(`kama`, lane_sort = len(LANES)+1) together with one row built from an unreadable prompt name
(`lane="-"`, `lane_round=None`, same lane_sort). Verified independently by the mutation lane
(their v1 `c25957` reproduced it; corrected on their current head `265571e2`).

Trigger class (unchanged): a file under `.ufo/prompts/` that is untracked
(`git ls-files -o --exclude-standard`) and does not match the checker's narrow
`^\.ufo/prompts/([a-z]+)-round-(\d+)\.md$` -- `kagi-x2-round-1.md` (the inner `-` is unspannable
by `[a-z]+`, so a hyphenated lane id lands in the unreadable bucket), `*-L1.md`, an uppercase
id. Same pair in the r13 checker (lines 1109 / 1225). Zero untracked prompts in the repo today,
so the live gate is not exposed; my generator's own selftest fixture mirror *was*, which is how
it surfaced.

Status at the executor handoff (`closure-check.py` sha256 `265571e2…`): the sort
crash was closed by the `_prompt_key_from_rel` pre-filter and `_sorted_debt`
ordering. Final integration (`0ac440f7…`) also guards the second parse before
unpacking, so the previously demonstrated bypass-filter arm is closed; the
final mutation campaign records that check.

One semantic gap remains: `_untracked_prompts` silently drops names
