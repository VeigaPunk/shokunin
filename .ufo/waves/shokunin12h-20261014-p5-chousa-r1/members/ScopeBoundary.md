### Contradiction 2: Downstream Propagation into Peer Deliverables

### Contradiction 3: Asymmetrical Finding-ID Severity in `FindingIds.md`
Sibling `FindingIds.md:202-209` attempted to address cross-lane scope boundaries under §3.12:
- `SCOPE_KASEGI_ABSORBED` → severity: **`warn`** (triggers `RESEARCH_GATE: DRIFT`)

This means an agent could commit extensive multi-agent dispatch and credit assignment procedures into a chousa research record, and the gate would happily certify the record as `CLEAN`! This severity disparity directly stems from the missing orchestration boundary in `PROVINCE.md`.

### Contradiction 4: Structural Gate Passing vs Semantic Scope Drift

`NO_QUESTION`, `NO_SOURCE_TABLE`, `UNRANKED_SOURCE`, `CHAIN_HOP_UNRESOLVED`, `CLAIM_UNPOINTED`, `REJECTION_DROPPED`, `NEGATIVE_WITHOUT_SWEEP`.
- **The Contradiction:** A research record that analyzes a live bug bounty target (violating `kasegi`), benchmarks an LLM's pass@k rate (violating `kengaku`), or defines swarm dispatch topologies (violating `kumitate`) will satisfy every single syntactic check! It has a question, a source table, a citation chain, and pointed claims. Without a domain-boundary check, the gate produces a false-clean verdict on out-of-province records.

## 4. The Proposed Move (UFO-FSD Connector Synthesis)

### Name: Four-Way Boundary Parity and Equal-Severity Gate Invariant

To resolve these contradictions and ensure chousa remains strictly within the general method domain, this seat proposes a single, coherent synthesis across the round's design proposals:

#### Move Component 1: Formal Contract Parity in `PROVINCE.md` and `SKILL.md`
Update `chousa-shokunin/PROVINCE.md:10-13` and `chousa-shokunin/SKILL.md:3, 34-39` to restore the 4-way boundary:
```markdown
**Refuses:** bounty-program scope and claim packages (→ kasegi); model-quality or
evaluation claims (→ kengaku); orchestration, dispatch, and multi-agent lifecycle
mechanisms (→ kumitate); external live-target research without operator approval
(loopback-only otherwise); secret values in any record (→ kagi for custody; shape-only here).
```

#### Move Component 2: Elevate `SCOPE_ORCHESTRATION_ABSORBED` to `warn` Severity
Align `FindingIds.md:208` so all three prohibited domains carry identical gate teeth:
```markdown
| id | sev | surface | subject | Produces when | Not this id when |
|---|---|---|---|---|---|
| `SCOPE_KASEGI_ABSORBED` | `warn` | record | `span=` | Bounty-program / claim-package scope absorbed into method record | Mentioned as refusal boundary only |
| `SCOPE_KENGAKU_ABSORBED` | `warn` | record | `span=` | Model-quality / benchmark / eval claims absorbed | Quoted as unverified specimen; routed to kengaku |
| `SCOPE_ORCHESTRATION_ABSORBED` | `warn` | record | `span=` | Dispatch, swarm wave, credit assignment, or agent lifecycle absorbed | Precedent citation (e.g. cite-check) or refusal note |
```
Any research record absorbing content from any of the three refused lanes triggers `RESEARCH_GATE: DRIFT` (exit 1).

#### Move Component 3: Normative Out-of-Province Routing Table in `QUALITY.md`
Incorporate the recommendation from `CraftVsContent.md:59-62` into `QualityBar.md` as criterion `Q-ROUTE` (Admission Criterion):
- When a research survey encounters findings outside chousa's domain (e.g., paper case-study numbers in `B`, artisan rank etymology in `A`, agent maturity ladders in `C`), the record **must not** absorb them into `chousa/corpus/knowledge/`.
- Instead, the record must file an explicit **`Out-of-Province Routing Table`** directing the finding to the appropriate fleet recipient (`kasegi`, `kengaku`, `kumitate`, `lore`, or operator). Silently dropping the finding violates `Q-REJ`; absorbing it violates `Q-BOUND`.

#### Move Component 4: Boundary Selftest Fixtures in `GateFixtureDesign`
Add three hermetic selftest fixtures for `tools/research-gate.sh --selftest`:
1. `record-fail-kasegi`: Contains bounty claim package analysis → exits 1 with finding `SCOPE_KASEGI_ABSORBED`.
2. `record-fail-kengaku`: Contains model benchmark evaluation → exits 1 with finding `SCOPE_KENGAKU_ABSORBED`.
3. `record-fail-kumitate`: Contains agent dispatch / swarm wave instructions → exits 1 with finding `SCOPE_ORCHESTRATION_ABSORBED`.
