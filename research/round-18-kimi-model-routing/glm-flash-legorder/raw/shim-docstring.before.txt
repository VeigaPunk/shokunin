#!/usr/bin/env python3
"""glm-flash-shim - OpenAI-compatible cascade shim (Python 3 stdlib only).

Sibling of ds-flash-shim. Exposes POST /v1/chat/completions and
GET /v1/models on 127.0.0.1:8793 and forwards every chat request through an
ordered 3-leg provider cascade, advancing to the next leg only when the
current leg FAILS.

Default legs (all overridable via env - see "LEG CONFIG" below):
  1. devin        POST http://127.0.0.1:8787/v1/chat/completions  (local
                  devin-shim; the body's `model` field is rewritten to the
                  devin slug "glm-5-3-flash-max" before forwarding)
  2. zai          POST https://api.z.ai/api/coding/paas/v4/chat/completions
                  (body forwarded as-is; model glm-5.3-flash is correct here)
  3. hyper        POST https://hyper.charm.land/v1/chat/completions
                  (body forwarded as-is)

FAILURE = advance to the next leg, on:
  * connection error / timeout (GLM_SHIM_TIMEOUT, default 15s)
  * HTTP 402 / 403 / 429
  * HTTP 5xx
  * HTTP 200 whose body (first GLM_SHIM_MARKER_BYTES, default 2048) contains a
    quota / balance / rate-limit / usage-exhausted marker
A 200 without those markers is SUCCESS.  If every leg fails, the LAST leg's
response (status + body) is returned to the caller.

Streaming: for `stream: true` the leg is chosen from the response HEADERS
before any body byte is streamed; the successful leg's bytes are then relayed
to the caller as-is.

LEG CONFIG (env vars, defaults are the module constants below):
  GLM_LEG1_NAME/URL/KEY/MODEL          leg 1 (devin)
  GLM_LEG2_NAME/URL/KEY/MODEL          leg 2 (zai)
  GLM_LEG3_NAME/URL/KEY/MODEL          leg 3 (hyper)
A leg's MODEL env var, when non-empty, replaces the request body's `model`
field for that leg (used by devin); empty means "pass the body through as-is".
Change a key by setting the matching env var (e.g. in the systemd unit's
Environment= lines) - no code edit required.
"""
