## A round (mechanics come from the addendum; session additions)

1. `inline.sh dispatch <lane>`, then one L1 `task` with no model parameter. Its prompt says:
   execute `.ufo/prompts/<lane>-round-<N>.md`. Add a session note of ≤10 lines: order position,
   repair-first if the previous closure was rejected, routed sibling sources, the prior private
   tree path (read-only input: reuse only what this round re-verifies inside the lane repo) and
   the time budget.
2. **Time budget.** At 2 h, message the L1: "freeze scope; land what verifies; file an honest
   report." At 3 h with no landed report, give it 20 min more. Then cancel the job, run
   `inline.sh fail`, and move the lane to the back of the order.
3. Then: `inline.sh verify`, then `inline.sh closure`, then a **fresh** closure `task` (never the
   L1, never resumed), then `inline.sh closed`, then `inline.sh advance`. Dispatch closures as soon
   as their round lands, in parallel with other lanes' rounds.
4. Each lane-round gets ≤2 attempts this session. Each closure gets ≤1 re-dispatch.

## Quality bar

- **Learning claim.** Each round must have ≥1 claim that changes what the lane knows or can do
  in its PROVINCE core or frontier. That means one of: admitted knowledge on uncovered ground; a
  stronger entry superseding a weaker one; a SKILL.md decision table or error pattern grounded in
  admitted entries; or a capability shown running and entered in SCORECARD's capability table.
  Gates, ledgers and tooling count only when they are the lane's own province and ran this round.
- **Claim sizing** (fleet lesson from the 12 rejections):
  - Declare each after-state as one concrete value that the closure can re-derive with one
    command over committed bytes. Size it to what one round can land and verify.
  - Use no universal clauses ("all", "complete", "every", "no harm anywhere") unless the counting
    command enumerates the full set.
  - A calibration claim must count mismatches between the lane's self-assessment
    (SCORECARD/SHONEN) and observed repo state. It cannot be an assertion.
  - Prefer 2 claims. Add a 3rd only if it is independent and cheap to verify.
  - Never narrow a target after landing: a miss is an honest stop.
- **Sources.** Primary sources, opened this round, each with a located quote. Rows are not
  knowledge. Every seat item names its claim and a concrete surface. ≥25% of each round's seats
  attack (reviewer, critic, mutation-tester, labrat). Executors only for code. Scribes for prose.

## Anti-loop rules

- **No meta work.** No protocol or aggregator rounds. No edits to the canonical protocol, fleet
  `PROTOCOL*.md`, `templates/` or `scripts/` beyond the one addendum amendment. No new campaign
  tooling, no settings changes, no new custody layers.
- **Repairs are capped.** A broken mechanical step (helper, validator, wave-slot) gets ≤30 min of
  repair from you. Then file an L0 line and route around it.
- **Same blocker twice in a lane** means an L0 line and park the lane. Never re-flag an unanswered
  L0 line byte-for-byte; point to it.
- **Refusals.** A safety or policy refusal on an item ends that item. Never reroute it to another
  provider or model ("automatic switch is not clearance"). Add the item to the holds in the ledger.
- **Never:** call `ask` (the session is unattended; use `.ufo/l0-questions.md`), poll in loops,
  resume dead identities, or dispatch a claimed round twice.
- **Never idle a free slot** while an eligible lane exists.
